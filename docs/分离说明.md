# 授权工具独立工程说明

迁移日期：2026-11-25。此仓库从 Quickhand POS 当前工作区迁入，包含最近对首次配置和 Inno Setup 编译器选择的修改。

## 工程边界

| 工程 | 作用 |
| --- | --- |
| LicenseKeyGenerator | 厂商使用的 WinForms 授权工具：首次配置、日常签发、旧授权入口、可选 POS 打包入口 |
| LicenseKeyGenerator.Core | RSA 签发、请求校验、签发记录、密钥导入、协议数据、旧格式兼容算法 |
| KeyGenerator | 保留的旧机器码显示／复制工具 |

均使用 .NET Framework 4.8。NuGet 依赖为 Newtonsoft.Json 13.0.1，保持本次拆分前的版本。本仓库不引用 POS 的 Common、Seals、Logger、DBAccess，也不引用其他仓库的源码或 bin 目录。

POS 的 Seals、Common 中的授权读取、签名验证、机器绑定、导入和受保护状态继续留在 POS 仓库，因为客户程序启动和使用授权需要这些代码。GGKey 是另一个功能的工程，不随授权签发工具移除。

## 兼容方式

独立类库的 `Protocol` 和 `Legacy` 来自现有授权实现，使用新的 `Quickhand.Licensing` 命名空间，避免与 POS 的类型冲突。RSA-3072、SHA-256、签名封装、版本号规则、旧 DES 文件格式、机器码和本地日期语义均保持一致。没有把数据库密码类或客户密钥复制进来。

`Protocol/SignedLicenseVerifier` 只使用显式传入的公钥，不携带客户程序的内嵌信任列表。签发工具保留内部 `LicenseGenerator` 命名空间以兼容原有测试调用；可执行文件已更名为 `LicenseKeyGenerator.exe`。

两个仓库各自保存必要的协议代码。以后如修改授权格式或校验规则，应同时检查两边，并执行 POS 仓库 `Scripts/Test-SignedLicense.ps1` 和 `Scripts/Test-LegacyLicense.ps1`，使用 `-LicenseToolsRoot` 指向本仓库；这些检查实际调用独立签发器，再用 POS 验证器验证，避免两边实现逐渐不一致。日常只改界面时可先运行本仓库独立检查。

## 首次配置与日常签发

- 本地偏好设置继续使用 `%LocalAppData%\QuickhandPOS\LicenseIssuer\profile.json`，原来选择的密钥路径可以继续使用；密码仍不保存。
- 原有 PFX、密码及 `license-issuance.jsonl` 不搬进本仓库，不重新生成。使用 **Use existing key...** 选择原来的密钥即可。
- **Choose source...** 现在选择包含 `SmartPOS/QuickhandPOS.csproj` 和 `Seals/Seals.csproj` 的 POS 源码目录。
- **Configure POS key** 仍只向选中的 POS 源码写入公钥。随后需要重新编译并部署 POS，客户程序才能信任新密钥。
- **Build POS / Build installer** 是可选的开发工作站功能，需要另外选择 POS 源码；生成授权本身不需要 POS 源码、数据库或 Inno Setup。
- 日常仍是：加载客户导出的请求 → 核对客户及功能 → 输入密码 → 确认购买权益 → 签发 → 客户导入。

不要把整个授权工具或签名私钥发给客户。客户只接收生成的授权文件和正式 POS 安装包。新建签名密钥会改变公钥信任关系，本次拆分不要求更换密钥。

## 原 POS 仓库的调整

已从 QuickhandPOS.sln 移除 LicenseGenerator 和 KeyGenerator；授权签发源码迁到本仓库。原目录仅保留迁移指引。授权兼容性测试更新为引用本独立工程的编译产物。运行时授权验证和客户信任列表不因拆分而修改。
